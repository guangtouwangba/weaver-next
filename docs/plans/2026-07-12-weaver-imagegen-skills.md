# Weaver Imagegen Skills Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add four host-image-model imagegen skills to Weaver — infographic (信息图), cover image (封面图), AI illustration, and image edit — modeled on the Cowart plugin and fused with baoyu's design system, plus the minimal MCP plumbing that lets a skill get a generated image onto the auditable Weaver canvas.

**Architecture:** Image generation is done by the **host** (Codex's built-in `image_generation_call`; text baked into the raster). A skill reads the generated bytes, calls a new agent-callable MCP tool `weaver_ingest_image` (base64 → server-side `sharp` validate + dedup + thumbnail → `assetId`), then places the image as an **image node via the existing ChangeSet review flow** (`weaver_submit_changeset` add-node). A second tool `weaver_render_svg_image` (SVG string → `sharp` PNG → asset) is the **dual-host fallback** for hosts without a built-in image model and for crisp-text infographics. Skills carry baoyu's design galleries/base-prompts as `references/*.md`.

**Tech Stack:** TypeScript, Zod, `@modelcontextprotocol/sdk`, `sharp` (already bundled, SVG→PNG verified), Vitest. Skills are markdown `SKILL.md` + Codex `agents/openai.yaml` sidecars, copied into the plugin by `scripts/build-plugin-release.mjs`.

---

## Context & Research (read before starting)

- **Cowart** (`github.com/zhongerxin/Cowart`) ships `cowart-image-gen` / `cowart-image-edit` skills. Its image-gen generates via the host's built-in imagegen, bakes text into the raster, resolves the actual output file carefully (never grabs a stale `generated_images` file), then inserts via one MCP tool. We mirror the *skill discipline* but route placement through Weaver's ChangeSet review instead of a direct insert.
- **baoyu skills** (`github.com/xuanxuan1983/baoyu-xuanyi-skills`): `baoyu-cover-image` and `baoyu-slide-deck` (editorial-infographic) are each `base-prompt.md` (design principles) + a **style gallery** (named styles: palette + elements + best-for). Design-system-driven. We adapt these (rewrite for investment-research, do not copy verbatim).
- **Our pipeline** is import-only. `weaver_import_image_asset` (base64+mimeType) and `weaver_create_content_node` are **widget-only** (`_meta.ui.visibility:["app"]`) — the agent cannot call them, hence the new `weaver_ingest_image`. `store.importImageAsset` (`packages/storage/src/assets.ts`) dedups by SHA-256, validates that the declared mimeType matches the real bytes via `sharp(...).metadata()`, writes a WebP thumbnail, does NOT change graphRevision.
- **sharp SVG→PNG is confirmed working** (incl. CJK text) with the bundled sharp: `await sharp(Buffer.from(svg)).png().toBuffer()`.
- **Dual-host caveat (accepted):** host AI image model is Codex-native; Claude Code has no built-in image model. Raster modes are Codex-primary; infographic/cover additionally support the SVG path (`weaver_render_svg_image`) so they work on both hosts.
- **Skill locations:** Codex skills in `skills/<name>/{SKILL.md,agents/openai.yaml}`; Claude skills in `tools/claude-skills/<name>/SKILL.md`. `scripts/build-plugin-release.mjs:54-57` copies `skills/` and `tools/claude-skills`. `plugins/weaver-next/.release-manifest.json` enumerates release files and is verified by `scripts/check-plugin-release.mjs`.

**Working style:** DRY, YAGNI, TDD, frequent commits. On the default branch, create a feature branch first: `git checkout -b feat/imagegen-skills`.

```markdown
# Infographic Design Principles (investment-research tuned)

Compose ONE self-contained infographic that a busy analyst reads in 10 seconds.

## Core principles
- **One takeaway.** A single bold title states the conclusion; everything supports it.
- **Information hierarchy.** Title > section headings > insights > supporting detail. Size, weight, and color encode importance.
- **Sectioned grid.** 3–6 clearly separated blocks on a consistent grid with generous whitespace. Never a wall of text.
- **Data callouts.** Pull key numbers out as large figures with unit + source. Trends → arrows/mini-charts, shares → proportion bars/rings.
- **Restrained palette.** One base + one accent + neutrals. Color carries meaning (up/down, categories), not decoration.
- **Iconography.** Simple flat icons label sections; no photographic or 3D elements.
- **Traceability.** A small source line (机构/报告 · 时点) at the bottom. Investment figures must be citable.

## Text
- All text is rendered IN the image, in the content's language, exactly as written — no placeholder text, no garbled glyphs.
- Title <= 14 chars. Section headings <= 10 chars. Insights one line.
- When text is dense or numbers must be exact, render via SVG (crisper than an image model).

## Archetypes
- `vertical-sections`: stacked labeled sections (default, portrait).
- `comparison`: 2–3 columns side by side (options/companies).
- `timeline`: left→right stages with dates.
- `hub-and-spoke`: central concept, radiating factors.
- `funnel`: narrowing stages (market → segment → target).
```

## Risks & Boundaries

- **Dual-host:** raster modes (illustrate/edit) are Codex-primary; infographic/cover work on both hosts via the SVG path. This is a deliberate, disclosed trade-off of the host-image-model choice.
- **Auditability preserved:** placement always goes through `weaver_submit_changeset` (Apply/Reject) — no direct graph writes, no `.weaver/*` writes, no ChangeSet bypass. Asset ingestion is content-addressed and does not change graphRevision.
- **No new heavy deps:** reuse the already-bundled `sharp`; no headless browser, no external chart lib.
- **Determinism/safety:** `weaver_render_svg_image` is deterministic; `weaver_ingest_image` validates that bytes match the declared mimeType (`sharp` metadata) and caps size.
- **Do not copy baoyu's files verbatim** — the reference galleries here are original, investment-research-tuned rewrites of the same design principles.
