六段管线

    
数据从图谱流到画布卡片,依次经过这六站 —— 这是一条真实的有序管线,所以用序号标注。


    

      

        
1

        
数据是结构 contracts/space.ts

        
内容存在 Graph 的类型化节点里,nodeContentSchema 是个判别联合:document / image / link / chart。一张图表节点存的是数据 + 语义,不是画好的图 —— 这让它能被 agent 经 ChangeSet 产出、可溯源、双宿主同源。

        
chart: { chartType:"line", title, unit,
  series:[{ name, color?, points:[{ label, value }] }],
  metric?, sourceNote?, asOf? }

        contracts/space.ts · contentKindSchema + nodeContentSchema
      


      

        
2

        
服务端读图 mcp/shared/graph-reads.ts

        
weaver_read_graph(resource:"full") → readProjectGraph → summarizeNode。这里把 document 的 markdown 裁掉省 agent 上下文,但 chart 的 content 全量带出。widget 收到 WidgetGraphNode[]。

        
content = node.content.kind === "document"
  ? { ...content, markdown: undefined } // 省上下文
  : node.content // chart / image / link 原样

        mcp/src/shared/graph-reads.ts · summarizeNode
      


      

        
3

        
映射成 React Flow 节点 hooks/useCanvasGraph.ts

        
每个图谱节点组装成一个 RF Node:type = contentKind 决定用哪个组件;data = CardData 按 kind 收窄取字段;位置/尺寸来自 LayoutDocument(非权威、可重排);主题以内联 CSS 变量注入。

        
{ id, type: item.contentKind,
  position: { x: frame.x, y: frame.y },
  data: { …, chart: item.content.kind==="chart" ? item.content : undefined },
  style: { --node-fill, --node-border, --node-accent … } }

        apps/widget/src/hooks/useCanvasGraph.ts
      


      

        
4

        
type → 组件 lib/graph-view.ts

        
一张注册表把 contentKind 映到组件。加一种数据类型 = 加一个 content kind + 注册一个渲染组件,就这么简单。

        
nodeTypes = { document: DocumentCard, image: ImageCard,
  link: LinkCard, chart: ChartCard, visualGroup: VisualGroupCard }

        apps/widget/src/lib/graph-view.ts · nodeTypes
      


      

        
5

        
纯函数几何 lib/chart-svg.ts

        
核心在这:layoutChart(spec, w, h) 是纯函数 —— 无 React、无 DOM、无随机,把 spec + 像素框算成几何(polyline 点、bar rect、pie 的 arc、坐标轴刻度、metric 涨跌)。对空 / NaN / 单点 / 全零都有兜底,所以可单测、确定性。

        
plotBox(w,h) → valueExtent(values) → linePoints() / bars() / pieSlices()
// 输入结构,输出可直接画的坐标,绝不抛异常

        apps/widget/src/lib/chart-svg.ts · layoutChart() + chart-svg.test.ts
      


      

        
6

        
内联 SVG components/nodes/ChartCard.tsx

        
组件把几何画成内联 <svg>(polyline / rect / path / text),颜色走 CSS 变量(--node-text / --node-border / --node-accent)+ 一个 6 色投研色阶;单序列回落到 accent 保持克制。ResizeObserver 驱动响应式重绘。

        
<svg viewBox="0 0 {w} {h}">
  <polyline points={line.polyline} stroke="var(--node-accent)" />
  <text …>{tick.label}</text>
</svg>

        apps/widget/src/components/nodes/ChartCard.tsx
      

    

  


  

    
为什么是这套

    

      
纯函数,可测
几何从 React 里剥离到 chart-svg.ts,已知输入 → 已知坐标,单测覆盖折线/柱/饼/涨跌与空数据兜底。

      
内联 SVG,双端一致
无外部图表库、无 CDN、无网络,受宿主 iframe 的 CSP 也没问题 —— Codex 面板与 Claude 浏览器逐像素相同。

      
token 着色,主题自适
颜色全走 --node-* 与 accent 变量,明暗主题由 canvas-theme.ts 算好注入,无一处硬编码 hex。

      
spec 与渲染分离
持有的是结构而非成品:同一份数据能重排、能换样式、能导出成别的格式。

    

  


  

    

      
同一个模子 → 演示 output

      
Deck 就是把这套复制一份

      
要在白板上出一份「演示 output」,不必另起炉灶:artifact 里存一份 slide spec,写一个 layoutSlide() 纯几何函数 + 内联 SVG 渲染器 —— 和 chart 完全同源。图谱是事实源,deck 是派生产物,改也走 Codex 重新生成。
