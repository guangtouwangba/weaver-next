### v4 方向修订（本节优先于下文遗留的 v3 树形表述）

- **核心工件升级为场景化语义空间**：底层是节点 + 有类型的关系；树只是七类视图之一。
- **项目固定场景包版本，视图可切换**：场景包定义节点/关系/上下文/Agent actions/布局偏好/产物；同一图谱可投影为自由画布、树、关系图、分组板、时间线、流程或表格。
- **布局是一等数据且与内容分离**：`graphRevision` 与每个视图的 `layoutRevision` 独立；手动拖放、固定、分组、连线路由、候选预览和撤销均持久化。
- **自然语言布局**：Canvas 将选择和视图状态同步给 coding agent；Agent 只生成 `LayoutPlan` 语义约束，确定性布局引擎生成坐标、候选与质量评分。
- **双轴节点**：场景语义 `type` 与内容形态分离。第一阶段内容形态为 Markdown document、project-local image Asset 和安全 enrichment 的 public link；媒体二进制不进入图谱 JSON，完整内容由 MCP 显式按需读取。
- **Codex 插件优先**：正式入口是原生 widget；MCP 提供结构化状态与 ChangeSet；Skills 提供稳定工作流；浏览器只用于开发预览。
- **原分支隔离保留**：它成为 branching/argument 等场景的 `ancestor_path` 上下文策略；其他场景可使用有类型邻域 + 用户钉选，禁止默认读取整个图。

## 0. TL;DR

- **方向一句话**：Weaver 把自然语言目标变成一个可由用户和 coding agent 共同维护、可自动布局、可切换结构的场景化语义空间。
- **核心问题**：思考天然是分支的（岔开/回溯/并比/汇合/剪枝），但 Chat 是单线程，**介质本身摧毁了思考的分支结构**。
- **核心交互**：**场景节点空间 + Canvas/Agent 双向任务**——用户编辑或选择节点，Agent 根据场景规则生成 ChangeSet 或 LayoutPlan，Widget 预览、应用和撤销。
- **核心工件**：**语义图谱 + 独立布局文档**；自由画布、树、关系图、分组板、时间线、流程和表格是同一份内容的不同视图。
- **核心赌注**：人定角度、AI 加速综合。AI 的角色是"思考副驾"——主动提议分叉、按分支隔离上下文、发现分支汇合、标记死胡同——而不是替你下结论。
- **差异化护城河**：①**按分支隔离上下文**（每条分支是干净上下文，NotebookLM/YouMind/ChatGPT 都没有）；②**论证结构可视可改可追**；③句子级引用接地 + 作用到成稿的 Voice。
- **MVP**：3 个页面，验证"分支式思考 + 成稿，明显比线性 Chat（ChatGPT/NotebookLM）更能帮人想清楚、写出来"。素材可选（纯靠 AI+想法也能用）、大纲可选（可从思维树直接成稿）。

## 1. 第一性原理：从问题出发

### 1.1 我们在为谁、解决什么

**用户**：深度内容创作者——长文自媒体、Newsletter 写手、独立记者、深度行业分析者。每篇产出 3,000–10,000 字，要有独特观点和叙事。

**真正的核心问题（v3 重新定位）**：
> 深度思考时，脑子里发生的不是线性问答，而是**分支**：一个问题岔出多个方向，走死一条回头换一条，两条线并排比较，发现两条其实相通，砍掉没用的枝。但我用的工具（ChatGPT、NotebookLM）都是**单线程对话**——我一旦岔开，要么覆盖掉之前的上下文，要么埋进滚动条。**我想的是一棵树，留下的却是一条线，事后完全看不见自己探索的形状。**

### 1.2 拆解「思考的分支」：六个动作

| # | 思考动作 | 说明 |
|---|----------|------|
| 1 | **岔开 (fork)** | 一个问题分出多个方向 |
| 2 | **回溯 (backtrack)** | 一条路走死，回到岔路口换一条 |
| 3 | **并比 (compare)** | 两条推理线并排对照 |
| 4 | **汇合 (merge)** | 发现两条分支其实相通 |
| 5 | **剪枝 (prune)** | 砍掉没用的枝 |
| 6 | **各带上下文 (context isolation)** | 每条分支有自己的前提和证据 |

**线性 Chat 为什么必然失败**：它是单线程，所有历史挤在一个上下文里，分叉只能靠"编辑消息重新生成"这种隐式、丢失树形的方式。思考的分支结构被介质摧毁。

### 1.3 「思考的可视化」其实是两件事

- **过程可视化**：我探索过的分支树——我在哪、试过什么、哪些还开着、哪些走死了。（解决"迷路"）
- **结果可视化**：从分支里结晶出的论点结构。（解决"成形"）

旧方向只做了第二件（论证大纲），漏了第一件——而本质恰恰主要是第一件。

### 1.4 核心设计原则：可视化是思考的副产品

> **可视化必须是思考的副产品，不是事后的整理工作。**

这是产品成败的关键。旧版 "Chat→Canvas 转化率低" 的根因，极可能就是**画布是额外的整理工作**——聊完还要手动搬。本设计让**「分叉」本身就是思考动作**（你通过提问来分叉），那张思维地图就**自己画出来了**，零额外成本。

由此推导出核心交互方向：**分叉式对话，自动布局成一棵可导航的思维树。**

## 2. 核心交互：分支对话树

### 2.1 机制：对话即树

**节点 = 一段思考 + 你的批注**（可以是一次问答、一段 AI 推理、也可以是你自己写下的一段想法，再附上你的批注/标记）。节点不被绑死成"一问一答"——它是一个可承载思考片段的单元。树不是聊完再画，而是**你每往下想一步，树就长一个节点**。

```
                    ● 起点：这个行业的增长逻辑变了吗？
                    │
        ┌───────────┼───────────────┐
   ● 是供给侧？   ● 是需求侧？      ● 是政策驱动？
        │              │                ✕（证据弱，剪掉，灰显折叠）
   ┌────┴────┐         │
 ●技术降本  ●产能过剩   ● 人口结构 ⟿⟿⟿ 与"技术降本"相通（跨枝连线·汇合）
   ●promising
```

### 2.2 六个分支动作 → 交互落点

| 思考动作 | 交互 | 关键设计 |
|----------|------|----------|
| **岔开** | 节点「分叉」按钮；**AI 答完主动提议**"这里有 N 个方向值得分开想"，点一下生成分支 | AI 主动提议分叉是最大价值点，开新枝摩擦降到一次点击 |
| **回溯** | 点任意旧节点→成为当前焦点，新输入从这里长出 | **旧分支不消失**，只失焦变灰——线性 Chat 给不了 |
| **并比** | 选两个节点/分支 → 并排面板对照 | 两条推理线真正能放一起看 |
| **汇合** | 跨枝拉连线；或「合并这两枝洞察」→ AI 综合成新节点 | 树是骨架，跨枝连线是叠加层 |
| **剪枝** | 标记分支为"死胡同" → 折叠 + 变灰 | 不删除，留作"我试过、走不通"的记录 |
| **各带上下文** | **每条分支的 AI 只看自己这一脉的祖先节点**，看不到兄弟分支 | ⭐ 分支树 > 线性 Chat 的根本原因 |

### 2.3 三个已定的核心设计决策

1. **追问默认「延长当前枝」**，分叉是显式动作 + AI 提议。
   *理由*：顺着想下去最自然；每句都炸开成树会乱。
2. **内容骨架是有类型的图，场景决定推荐视图和上下文策略**。
   *理由*：brainstorming、词汇、人物、因果和时间线具有不同结构；通过 LayoutPlan + 确定性引擎解决手动整理痛点，而不是把所有场景压成树。
3. **节点折叠态只显示一句话主旨，展开看完整问答 + 句子级来源引用**。
   *理由*：保证树在缩放时读得清；引用接地对标 NotebookLM（见 §3）。

### 2.4 AI 的角色：思考副驾，不是答题机

- **主动提议分叉**：答完指出"这里其实有几个该分开想的方向"。
- **按分支隔离上下文**：在分支 B 里不被分支 A 的假设污染（§2.2 第 6 条，是技术护城河不只是 UI）。
- **发现汇合**：提示"你这两条分支其实在说同一件事"。
- **标记死胡同 / 缺口 / 反例**：帮你看清论证的薄弱处。
- **不替你下结论**：人定角度，AI 加速综合。

> **技术护城河说明**：线性 Chat 所有历史混在一个上下文窗口，越聊越脏；分支树里每条分支只继承自己的祖先链。这是 NotebookLM / YouMind / ChatGPT 都没有的能力——它们的"编辑消息重新生成"是隐式分叉，丢掉了树。

## 3. 产品定位与差异化

**对外叙事/定位一句话**：
> **Weaver 是「思维树 / 分支式思考工具」——别人给你一条对话线，Weaver 让你像分叉一样思考、看见自己的思路，需要时再把它织成文章。**

- **首要用户**仍是深度内容创作者（思考清楚是写好的前提），但产品**不依赖"先有素材"**——拍脑袋纯想一个问题也能用（见 §4.1、§7）。这把产品从"基于素材的创作工具"正式定位为**通用的分支思考工具**，创作只是它最自然的下游出口。
- （竞品分析结论：YouMind 已占据"创作工作台"泛位置，正面硬刚不可取。Weaver 的纵深在**思考的分支与可视化** + **论证可视可追**，这是两家的共同真空。详见 `competitive-analysis-2026.md`。）

| 对标 | 它强在 | Weaver 不在这比 | Weaver 的差异武器 |
|------|--------|------------------|--------------------|
| **NotebookLM** | 来源接地问答、播客/视频、引用准（幻觉~13%）、免费 | 播客、免费额度 | 分支思维 + 上下文隔离 + 成稿与声音 |
| **YouMind** | 创作闭环、多格式、浏览器捕获 | "创作闭环广度" | **论证深度与可信**：思考可视可追、人定角度 |
| **ChatGPT / Claude** | 通用智能、起草 | 模型智能本身 | 思考留得下结构、上下文不互相污染 |
| **Notion / Obsidian** | 存放、双链 | 通用笔记 | 不止存放——**主动帮你把思考织成论证** |

**一句话护城河**：别人给你一条对话线，Weaver 给你一棵能回看、能比较、能结晶的思维树。

### 3.1 从竞品学来的硬指标（写进验收）
- **句子级 inline 引用接地**：节点回答与成稿引用可点击直达原文，对标 NotebookLM 低幻觉。设为 **P0**。
- **开放/导出优先**：数据归属、可导出、自托管——对抗 NotebookLM"金丝笼"，是开源叙事的真资产。
- **Voice 作用到成稿**：区别于 NotebookLM Persona 只管 Chat。设为 **P0** 差异点。

## 4. 完整愿景：能力清单

围绕「思考」组织，分四块。（P0 核心 / P1 重要 / P2 锦上添花）

### 4.1 喂养思考：素材接地 (Ground) —— **可选**
> 素材是**可选的接地来源**，不是前提。无素材时，思维树纯靠"AI + 我的想法"分支思考；有素材时，节点回答基于素材并带引用。这是产品作为"通用分支思考工具"的关键。
- `P0` 速记 inbox：随手记一句话/灵感
- `P0` 多源导入：URL 抓取、PDF、纯文本/Markdown 粘贴（可选，用于接地）
- `P0` 有素材时，思维树节点回答基于素材，带句子级引用
- `P1` 阅读视图：高亮、批注 → 高亮可作为思维树的起点节点
- `P1` 视频/播客转写导入；浏览器扩展捕获（YouMind 公认最值功能）
- `P1` 大文档完整处理（按章节分段、全文覆盖、可见进度）
- `P2` OCR / 扫描件；图表/表格提取

### 4.2 分支思考：思维树 ⭐ 核心 (Think)
- `P0` 分支对话树：对话即树、自动布局、可平移缩放
- `P0` 显式分叉 + **AI 主动提议分叉**
- `P0` 回溯（点旧节点为焦点，旧枝保留）
- `P0` **按分支隔离上下文**（每枝只继承祖先链）
- `P0` 节点折叠/展开（主旨 ↔ 完整问答+引用）
- `P0` 剪枝（标记死胡同、折叠灰显）
- `P1` 分支并排对比
- `P1` 跨枝连线 + AI 合并洞察（汇合）
- `P1` AI 标记缺口/反例
- `P2` 跨项目思维树关联（全局思考网络）

### 4.3 结晶成形：论证大纲 (Crystallize) —— **可选中间层**
> 论证大纲是**可选**的中间层，不是成稿的强制关卡。用户可以从思维树直接生成初稿（见 4.4），也可以先把好分支结晶成大纲、再成稿。
- `P0` 把节点/分支「提升」为论点，组织成可重排的论证大纲（思维树的结晶视图）
- `P1` AI 提议大纲骨架（基于已选分支自动排一版）
- `P1` 叙事检查：顺序是否有说服力、是否有逻辑跳跃
- `P2` 多种结构模板（论说文 / 分析报告 / 故事化）

### 4.4 落地产出：成稿与发布 (Ship)
- `P0` **从思维树直接生成初稿**（选若干分支/节点即可成稿，论证大纲可选不经过）
- `P0` 从论证大纲生成带行内引用的初稿（走结晶路径时）
- `P0` 长文编辑器 + **Voice**（MVP 用**预设 tone**：如学术/轻松/专业；P1 再做"喂范文学风格"）
- `P0` 导出 Markdown
- `P1` 段落级 AI 操作（扩写/精简/换角度/找更强证据）
- `P1` 多格式产出（Newsletter / X Thread / DOCX）——**均从同一论证大纲派生，保证主题一致**（对标 NotebookLM 多格式主题不一致的痛点）
- `P1` 思维树/大纲导出 PNG/SVG
- `P2` 事实核查；一键发布平台

## 5. 页面全景（完整愿景：5 个页面）

> 核心交互聚合后，页面大幅简化——原"阅读/综合/大纲"被「思维树」吸收（综合就是在树上分叉/并比/汇合/剪枝）。

```
┌────────────┐
│ 0 工作台    │  所有项目 + 速记 inbox + 新建
└─────┬──────┘
      │ 进入一个项目（= 一个思考主题/一篇要产出的内容）
      ▼
┌──────────────────────────────────────────────────────────┐
│  2 思维树工作台 ⭐（绝大多数时间在这）                       │
│  ┌──────────┬──────────────────────────┬───────────────┐  │
│  │素材侧栏   │   分支对话树（核心画布）    │  节点详情/对比 │  │
│  │(可选·接地)│   对话即树·自动布局         │  /引用溯源    │  │
│  └──────────┴──────────────────────────┴───────────────┘  │
│            ↓ 选分支直接成稿  或  ↓ 先结晶成大纲再成稿        │
│  3 成稿：（论证大纲·可选）→ 带引用初稿 → 导出                 │
└──────────────────────────────────────────────────────────┘
┌────────────┐
│ 4 设置      │  模型 / Voice / 项目配置 / 导入源
└────────────┘
```

| # | 页面 | 目的（解决哪件事） | 核心交互 | 关键对象 |
|---|------|---------------------|----------|----------|
| 0 | **工作台 Dashboard** | 启动/回到工作；接住灵感 | 新建项目、项目卡片、速记 inbox | Project, QuickNote |
| 1 | **素材 Sources**（**可选**接地；可作侧栏，亦可独立全屏） | 喂养思考：管理来源、阅读高亮 | 导入、阅读、高亮→起点节点 | Source, Highlight |
| 2 | **思维树工作台 Think** ⭐ | 分支思考 + 可视化（产品心脏） | 对话即树、分叉、回溯、并比、汇合、剪枝 | ThoughtNode, Branch, Relation |
| 3 | **成稿 Draft**（论证大纲为可选中间层） | 从分支直接成稿，或先结晶再成稿 | 提升为论点(可选)、生成带引用初稿、Voice(预设 tone)、导出 | Outline(可选), Draft, Citation, Voice |
| 4 | **设置 Settings** | 配置 | 模型、Voice、项目设置 | ModelConfig, Voice |

> 1 与 2 可合（素材作侧栏）、3 可作为 2 的下游面板。完整愿景按独立性算 5 页，聚合后实际体验更紧凑。

## 6. 功能点清单（按优先级汇总）

## 7. MVP 切分

### 7.1 MVP 要验证的唯一核心假设
> **"分支式思考 + 结晶成稿，明显比线性 Chat（ChatGPT / NotebookLM）更能帮深度思考者想清楚、并写出来。"**

更具体的体感验证：用户愿意在 Weaver 里"分叉地想问题"，并且**回头看自己的思维树觉得有用**（而不是觉得是负担）。

### 7.2 MVP 范围：贯穿"想→写"最薄的一刀

**MVP 页面（3 个）**：

| # | MVP 页面 | 包含 | 砍掉 |
|---|----------|------|------|
| 0 | **工作台** | 项目列表、新建、速记 inbox | 复杂筛选 |
| 1 | **思维树工作台（含可选素材侧栏）** ⭐ | 分支对话树（对话即树/分叉/AI提议分叉/回溯/折叠/剪枝/上下文隔离）；节点=一段思考+批注；**无素材也能纯靠 AI+想法分支思考**；有素材时句子级引用 | 并排对比、跨枝连线/汇合、缺口检测、阅读高亮、视频转写 |
| 2 | **成稿** | **从选中分支直接生成带引用初稿**（大纲可选）→ Voice(预设 tone) → 导出 Markdown | 强制大纲、多格式、段落级花活、叙事检查、事实核查 |

**MVP 必含功能点**：
1. 分支对话树：对话即树、显式分叉 + **AI 主动提议分叉**、回溯、折叠/展开、剪枝；**节点 = 一段思考 + 批注**
2. **按分支隔离上下文**（最核心的技术差异，必须在 MVP）
3. **无素材也能跑通**（纯靠 AI + 我的想法分支思考）；导入 URL/PDF/粘贴文本作为**可选**接地
4. 有素材时，节点回答带句子级可点击引用
5. **从选中分支/节点直接生成带行内引用初稿**（论证大纲为可选，不强制）
6. 长文编辑器 + Voice（MVP 用**预设 tone**：学术/轻松/专业）
7. 导出 Markdown

**MVP 明确不做**：自由画布、并排对比、跨枝汇合、缺口/反例检测、阅读高亮、视频/播客转写、浏览器扩展、多格式产出、跨项目网络、协作、OCR、Podcast。

### 7.3 MVP 成功标准
- 用户能用 Weaver 独立完成一次真实的分支思考 → 一篇带引用初稿。
- 关键转化：**节点分叉率**（用户是否真在分支地想）、**分支→初稿完成率**（含直接成稿与经大纲两条路径）。
- 定性：5 个目标用户里 ≥3 个说"分支地想比我在 ChatGPT 里来回滚屏强，我愿意继续用"，且**认可'回看自己的思维树'有价值**。

## 8. 成功度量（继承 PRODUCT.md，按思维树调整）

- **北极星**：每周**走完"分支思考→结晶→带引用初稿"全流程**的项目数。
- **核心 aha moment**：用户第一次**回看自己的思维树**、并把一条 promising 分支一键结晶成结构的那一刻。
- **关键漏斗**（替换旧版 Chat→Canvas→Output）：
  `素材接地 → 节点分叉(产生分支) → 分支提升为论点 → 排出大纲 → 生成初稿 → 导出`
- **取代旧 Chat→Canvas 转化率的新核心指标**：**节点分叉率**（衡量"分支地想"是否真发生）+ **思维树回看率**（衡量可视化是否有用而非负担）。
- PRODUCT.md 第 7–14 章度量/监控/反馈/数据质量框架整体复用，把"Canvas"相关指标换成"思维树/分支"相关指标。

## 9. 风险与待验证假设

| 假设 | 风险 | 验证方式 |
|------|------|----------|
| 用户真的"分支地想"，且愿意显式分叉 | 可能习惯线性提问，懒得分叉 | 看 MVP 节点分叉率；观察 AI 提议分叉的采纳率 |
| "回看思维树"是价值而非负担 | 可能树一大就乱、看不懂 | 自动布局 + 折叠 + 焦点高亮；定性问"回看有用吗" |
| 按分支隔离上下文带来可感知的更好回答 | 用户可能感知不到差异 | A/B：隔离 vs 不隔离的回答质量盲测 |
| 思维树能顺畅结晶成稿 | 提升/排大纲可能很别扭 | MVP 真实跑通"分支→论点→初稿" |
| Voice 能产出"有我声音"的初稿 | "AI 味"是头号劝退 | Voice 开/关定性对比 |
| 不与 YouMind 比创作闭环广度的取舍正确 | 可能用户就是要一站式多格式 | 守住"思考深度+可信"纵深，多格式放 P1 |

## 10. 已决议（2026-06-22 拍板）

1. **节点粒度**：✅ 节点 = **一段思考 + 批注**（不绑死一问一答；可承载问答/AI推理/用户自写想法+批注）。
2. **MVP Voice 路线**：✅ MVP 用**选预设 tone**（学术/轻松/专业）；"喂范文学风格"放 P1。
3. **素材的地位**：✅ 素材**可选**——允许"无素材纯靠 AI + 我的想法"分支思考。产品定位为**通用分支思考工具**，创作为最自然下游。
4. **结晶的强制度**：✅ 论证大纲为**可选中间层**——允许从思维树**直接生成初稿**，也可先结晶再成稿。
5. **对外叙事**：✅ 新叙事 = **「思维树 / 分支式思考工具」**，取代旧的"Open-Source NotebookLM Alternative with Infinite Canvas"。（README 改写时机：MVP 形态稳定后统一更新对外文案。）

### 仍待评审的新问题
- **AI 提议分叉的触发与节制**：每次回答都提议会不会打扰？提议几个方向合适？需在原型里调。
- **思维树规模上限**：单项目节点数到多少会让"回看"变负担？是否需要自动归并/聚焦机制。
- **无素材模式下的引用**：纯 AI+想法时没有出处，如何标注"这是 AI 推断 / 这是我的判断"以保持可信（沿用 PRODUCT.md 的 `inferred` 诚实原则）。
